# SIt_konspect
HTTP-методы: семантика, свойства и статус-коды
Любой HTTP-API предназначен для управления ресурсами. К каждому ресурсу обращаются по уникальному URL, а HTTP-метод определяет, что именно нужно сделать с этим ресурсом.
## Назначение HTTP-методов

| Метод  | Назначение                        | Пример использования   |
|:-------|:----------------------------------|:-----------------------|
| GET    | Получение ресурса или коллекции   | `GET /posts/5/`        |
| POST   | Создание нового ресурса           | `POST /posts/`         |
| PUT    | Полная замена существующего ресурса | `PUT /posts/5/`      |
| PATCH  | Частичное изменение ресурса       | `PATCH /posts/5/`      |
| DELETE | Удаление ресурса                  | `DELETE /posts/5/`     |

HEAD  получает только заголовки ответа (без тела). Аналог GET, но экономит трафик.
OPTIONS  возвращает список методов, которые сервер поддерживает для данного URL. Часто используется браузером при CORS-запросах.

Как не надо называть эндпоинты
Не дублируйте действие метода в имени ресурса. API должен понимать команду по самому HTTP-методу:
Правильно:    GET    /users/
Правильно:    POST   /users/
Неправильно:  GET    /get-users
Неправильно:  POST   /create-user

Три ключевых свойства HTTP-методов
У каждого метода есть три характеристики, описанные в спецификации HTTP. Они важны для правильной работы браузеров, кешей, балансировщиков и промежуточного ПО.
1. Безопасность (Safe)
Метод считается безопасным, если он не изменяет состояние сервера. Клиент может вызывать его сколько угодно раз без риска побочных эффектов.
Безопасные: GET, HEAD, OPTIONS
Небезопасные: POST, PUT, PATCH, DELETE
Пример: GET /users/123 только читает данные. Даже если вызвать его 1000 раз, профиль пользователя не изменится.

2. Идемпотентность (Idempotent)
Метод идемпотентен, если многократное выполнение одного и того же запроса даёт тот же результат на сервере, что и однократное. Состояние сервера после N одинаковых запросов не отличается от состояния после 1 запроса.
Идемпотентные: GET, HEAD, OPTIONS, PUT, DELETE
Неидемпотентные: POST, PATCH 
Пример PUT: PUT /posts/5/ {title: "Новое название"} → если отправить этот запрос 5 раз, пост всё равно будет иметь только одно название.
Пример DELETE: первый запрос удаляет ресурс, последующие вернут 404 Not Found, но состояние сервера останется неизменным (ресурс уже удалён).
Пример POST: POST /orders/ → каждый вызов создаст новый заказ. 10 запросов = 10 заказов.

3. Кешируемость (Cacheable)
Определяет, можно ли автоматически сохранять ответ в HTTP-кеше (браузер, CDN, прокси).
Кешируемые по умолчанию: GET, HEAD
Не кешируемые: POST, PUT, PATCH, DELETE
## HTTP-методы: основные свойства

| Метод   | Безопасен | Идемпотентен      | Кешируем | Изменяет данные |
|:--------|:---------:|:-----------------:|:--------:|:---------------:|
| GET     | Да        | Да                | Да       | Нет             |
| POST    | Нет       | Нет               | Нет      | Да              |
| PUT     | Нет       | Да                | Нет      | Да              |
| PATCH   | Нет       | Не гарантируется  | Нет      | Да              |
| DELETE  | Нет       | Да                | Нет      | Да              |
| HEAD    | Да        | Да                | Да       | Нет             |
| OPTIONS | Да        | Да                | Нет      | Нет             |

HTTP-статус коды: что означают и когда возвращать
Сервер отвечает на каждый запрос трёхзначным кодом. Первая цифра определяет класс ответа:
## Классы HTTP-статус кодов

| Класс | Значение          | Когда используется                                                                 |
|:------|:------------------|:-----------------------------------------------------------------------------------|
| 1xx   | Информационный    | Запрос принят, обработка продолжается (редко используется в API, например 100 Continue) |
| 2xx   | Успех             | Запрос выполнен успешно                                                            |
| 3xx   | Перенаправление   | Клиенту нужно обратиться по другому URL                                            |
| 4xx   | Ошибка клиента    | Запрос некорректен, не хватает прав или ресурс не найден                           |
| 5xx   | Ошибка сервера    | Сервер не смог выполнить корректный запрос                                         |

## Основные HTTP-статус коды

| Код  | Название                | Когда возвращать                                                                 |
|:-----|:------------------------|:---------------------------------------------------------------------------------|
| 200  | OK                      | Успешный `GET`, `PUT`, `PATCH`, `DELETE` (если в теле есть данные)            |
| 201  | Created                 | Успешный `POST` (новый ресурс создан)                                            |
| 204  | No Content              | Успешный `DELETE` или `PUT`/`PATCH` без тела ответа                             |
| 301  | Moved Permanently       | Ресурс перемещён навсегда (клиент должен обновить закладку)                     |
| 304  | Not Modified            | Кеш клиента актуален (часто для `GET` с `If-Modified-Since`)                    |
| 400  | Bad Request             | Ошибка в данных клиента (невалидный JSON, пустое поле, неверный формат)         |
| 401  | Unauthorized            | Клиент не аутентифицирован (нет токена/логина)                                  |
| 403  | Forbidden               | Клиент аутентифицирован, но **не имеет прав** на действие                       |
| 404  | Not Found               | Ресурс не существует                                                             |
| 405  | Method Not Allowed      | Метод не поддерживается для этого URL (например `DELETE` на `/users/`)          |
| 409  | Conflict                | Конфликт данных (дубликат email, оптимистическая блокировка)                    |
| 422  | Unprocessable Entity    | Данные валидны по формату, но логически неверны (часто в DRF)                   |
| 429  | Too Many Requests       | Превышен лимит запросов (Rate Limiting)                                         |
| 500  | Internal Server Error   | Неожиданная ошибка на сервере (баг, падение БД)                                 |
| 502/503 | Bad Gateway / Service Unavailable | Сервер недоступен, перегружен или на техобслуживании                      |
